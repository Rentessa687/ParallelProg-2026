# Лабораторная работа 2: метод Якоби (OpenMP)

Параллельная версия решателя из [лабораторной работы 1](../lab1). Формат входных
и выходных данных не изменился; в выходной файл добавлена строка `threads <p>`.

## Состав

| Файл               | Назначение                                                              |
|--------------------|--------------------------------------------------------------------------|
| `jacobi.cpp`       | Метод Якоби; при сборке с OpenMP внешний цикл по `i` выполняется параллельно |
| `generate_data.py` | Генерация диагонально доминирующей СЛАУ (4-й аргумент — коэффициент доминирования) |
| `verify.py`        | Верификация через `numpy.linalg.solve`                                  |
| `benchmark_omp.py` | Серия экспериментов: размеры × число потоков, CSV и графики             |
| `Makefile`         | Сборка `jacobi_omp` (OpenMP) и `jacobi_seq` (тот же код без OpenMP)     |

## Реализация

В каждой итерации метода Якоби вычисление `x_new[i]` не зависит от других
`x_new[j]`, поэтому цикл по `i` распараллелен директивой
`#pragma omp parallel for reduction(+:diff_sq) schedule(static)`. Норма
разности `||x_new - x_old||` считается в том же цикле через редукцию.
Векторы `x` и `x_new` меняются местами указателями, без копирования.
Последовательная версия `jacobi_seq` собирается из того же `jacobi.cpp` без
`-fopenmp`, поэтому ускорение считается относительно неё: `S_p = T_seq / T_p`.

## Сборка

Linux:

```bash
make
```

macOS (Apple clang не содержит OpenMP, нужна библиотека libomp):

```bash
brew install libomp
make
```

При использовании Homebrew GCC:

```bash
make CXX=g++-15 OMP_FLAGS=-fopenmp OMP_LIBS=
```

## Запуск

```bash
python3 generate_data.py 2000 input.txt 42
./jacobi_omp input.txt output.txt 1e-8 100000 4
python3 verify.py input.txt output.txt
```

Параметры `jacobi_omp`: `<input_file> [output_file] [eps] [max_iter] [threads]`.
Если `threads` не указан, используется `OMP_NUM_THREADS` или число ядер по умолчанию.

## Серия экспериментов

```bash
python3 benchmark_omp.py
```

По умолчанию: `n = 200, 400, 800, 1200, 1600, 2000`, потоки `1, 2, 4, 8, 10`,
10 запусков на конфигурацию (после одного прогревочного), в таблицу попадает
медиана. Результаты — в `results.csv` и `results_plot.png`.

Полезные параметры: `--sizes`, `--threads`, `--reps`, `--eps`, `--max-iter`,
`--dominance` (меньшее значение даёт больше итераций и более тяжёлую задачу),
`--out`, `--plot`, `--keep`.
